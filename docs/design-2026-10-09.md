# turnwise — original design note (2026-10-09)

> Kept as the record of the first day's decisions. The README is the current description; since this was written, LLM summaries/titles/action items, folders, dedupe by content hash, the PWA, and a remote Ollama option were added.

Self-hosted meeting transcription on this machine (RTX A2000 12GB), reachable
over the tailnet from the phone, with a notes repository and a Claude skill.

## Requirements (from the user)
- Notes repository on this machine.
- Web app on the Tailscale network: record live, or upload a recording (big files ok).
- Transcribe like pocket.ai: best open-source models, English + Hindi + mixed.
- Phone recordings with background noise → noise removal.
- Speaker diarization ("Speaker 1, 2…"), later name speakers globally so they are recognised.
- Use the GPU.
- A Claude skill that transcribes a file and retrieves transcripts from the knowledge base.

## Assumptions (not asked, decided)
- Output per turn: Hinglish in Latin script + English translation (user asked mid-build). Raw ASR text (may contain Devanagari) is kept in `text`.
- Tailnet-only access is enough; no login.
- Transcription happens after the recording stops, not live streaming (same as pocket.ai).

## Stack
| Step | Choice | Why |
|---|---|---|
| Denoise | DeepFilterNet3 static binary (`bin/deep-filter`), attenuation capped (default 30 dB), toggle per job | zero python deps, fast on CPU; full suppression would gate far-field speakers |
| Diarize | pyannote `speaker-diarization-community-1` on GPU, `exclusive_speaker_diarization` output | best open diarizer; exclusive output aligns with transcripts |
| ASR | Qwen3-ASR-1.7B via `qwen-asr`, `language="English"` + romanised Hinglish context (tested on real clips: gives Latin-script Hinglish, Hindi words sometimes Devanagari). faster-whisper large-v3 fallback (`ASR_BACKEND=whisper`) tested far worse (misdetected Malay, translated) | Qwen: Hindi native, noise-robust, best on the user's clips |
| Hinglish + English | Ollama `qwen3.5:9b` structured output, 15 turns per request, GPU models unloaded first | already installed; ~33 tok/s; LLM handles romanisation + translation with context |
| Speaker memory | pyannote embedding model, cosine match against `speakers.json` (threshold setting, default 0.55) | names learned when the user renames a speaker |
| Server | FastAPI + one worker thread, localhost:8470, `tailscale serve --https=8446` | getUserMedia needs HTTPS; one process owns the GPU |
| UI | single `static/index.html`, vanilla JS, Apple HIG feel (system font, semantic colors via `prefers-color-scheme`, 44px targets, inset-grouped lists) | no build step |
| Skill | `~/.claude/skills/audio-notes/SKILL.md` wrapping `cli.py` | list/search/show read the notes dir directly; transcribe posts to the server |

## Data layout
```
~/notes/audio/                       NOTES_DIR
  speakers.json                      {"Rahul": {"model": "...", "embeddings": [[...], ...]}}
  settings.json                      {"match_threshold": 0.55, "denoise": true, "atten_db": 30}
  2026-10-09-1830-weekly-sync/
    audio.m4a                        original upload / recording
    transcript.json                  see schema
    transcript.md                    human/Claude readable
    status.json                      {"state": "queued|denoise|diarize|transcribe|done|error", "detail": "..."}
```
transcript.json:
```json
{"id": "2026-10-09-1830-weekly-sync", "title": "Weekly sync", "created": "2026-10-09T18:30:00",
 "duration": 1832.4, "language": "auto", "backend": "qwen3-asr-1.7b",
 "speakers": {"SPEAKER_00": "Rahul", "SPEAKER_01": null},
 "segments": [{"start": 0.0, "end": 4.2, "speaker": "SPEAKER_00", "text": "<raw ASR>", "hinglish": "...", "english": "...", "lang": "Hindi"}]}
```

## Pipeline (pipeline.py)
1. ffmpeg → 48 kHz mono wav → (optional) deep-filter → ffmpeg → 16 kHz mono wav.
2. Diarize (GPU). If no HF_TOKEN or model not accepted: one speaker, status detail explains.
3. `ASR_MODE=window` (default): transcribe 3-minute windows cut at silence (conversational context), align every word with
   torchaudio's MMS forced aligner (Hindi supported; text romanised with uroman for alignment only), give each word the speaker
   whose exclusive turn contains it, group runs into segments. `ASR_MODE=turns`: merge adjacent same-speaker turns (≤ 30 s) and
   transcribe each clip separately. Verified equal on a 3-min clip; window mode kept for long multi-speaker meetings.
4. Batch inference on GPU.
5. Speaker embeddings come from the pyannote output (centroids); match against speakers.json.
6. Unload GPU models; Ollama pass fills `hinglish` / `english` per turn (falls back to raw text with a warning if Ollama is down).
7. Write transcript.json / transcript.md, status done.
Models load lazily, stay resident, unload after 10 min idle. CUDA OOM → status error says `ollama stop`.

## Web app (server.py)
- `POST /api/upload` (stream to disk, title) → job
- `POST /api/record/{id}/chunk` append MediaRecorder blob; `POST /api/record/{id}/finish` → job
- `GET /api/notes`, `GET /api/notes/{id}`, `DELETE /api/notes/{id}`, `GET /api/notes/{id}/audio`
- `PATCH /api/notes/{id}` title / speaker names (names also saved to speakers.json with embeddings)
- `GET /api/search?q=` grep over transcript.md
- `GET/PUT /api/settings`, `GET/DELETE /api/speakers/{name}`
- `POST /api/notes/{id}/retranscribe`
